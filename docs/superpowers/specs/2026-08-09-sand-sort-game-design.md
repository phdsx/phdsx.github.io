# 沙子分类网页游戏设计规格

## 目标

在现有 PHDSX 静态站点中新增一款可直接游玩的沙子分类网页游戏。游戏参考 Y8 的 `Sand Sort: Color Puzzle` 核心画面、操作节奏和反馈，但只实现游戏本体，不复制 Y8 的导航、推荐内容、登录、隐私弹窗或广告系统。

原作中需要观看广告才能使用的能力全部保留，并改为不受广告或付费次数限制的免费功能。成品不得包含广告请求、广告占位、付费入口、倒计时解锁、站外链接或第三方运行时依赖。

## 用户体验

### 游戏流程

1. 玩家从简短的开始页进入游戏。
2. 第一关使用覆盖式教学卡解释“选择瓶子”和“倒入目标瓶子”。
3. 玩家依次点击或触摸源瓶和目标瓶完成倒沙。
4. 每个瓶子最终只包含一种颜色时显示通关粒子和弹窗。
5. 玩家进入下一关，当前进度自动保存。

计划提供 30 个递进关卡。教学关从两种颜色开始，随后逐步增加颜色、瓶子和需要腾挪的层数。所有发布关卡必须通过可解性检查。

### 倒沙规则

- 只有非空瓶可以作为源瓶。
- 目标瓶必须为空，或顶部颜色与源瓶顶部颜色相同。
- 目标瓶必须仍有容量。
- 一次操作尽可能移动源瓶顶部连续的同色沙层，移动量受目标瓶剩余容量限制。
- 已满且颜色完全一致的瓶子视为完成。
- 所有非空瓶都完成时关卡胜利。

### 免费功能

底部工具栏保留以下能力，全部免费使用，不消耗广告次数、体力、金币或真实货币：

- 撤销：恢复上一份有效操作快照。
- 提示：计算并高亮一个合法且有价值的移动。
- 重排：使用可逆打散操作重新生成当前关布局；打散步骤的逆序全部是合法倒沙，因此结果保持可解。
- 增加空瓶：给当前关临时增加一个空瓶；每局同时最多保留一个额外瓶，重开或切关后可再次免费添加。
- 重开：恢复当前关初始状态。

金币与体力只用于还原原作顶部状态栏的视觉语言。体力始终显示为充足，金币可随通关增长，但两者都不限制游玩，也不能购买或解锁任何内容。

## 视觉与动画

游戏使用深蓝夜色背景、中央瓶架、彩色颗粒沙层、带高光与描边的玻璃瓶，以及紧凑的顶部状态栏。桌面端将游戏场景居中显示；手机端铺满可用竖屏区域，并保持触摸目标足够大。

核心反馈包括：

- 源瓶选中后上浮并出现柔和发光描边。
- 有效倒沙时源瓶移动到目标上方并倾斜。
- 沙粒沿弧线落入目标瓶，并在落点产生轻微粒子飞散。
- 非法移动通过瓶子摇晃和短文本提示反馈。
- 通关时播放彩纸、光点和完成弹窗动画。
- 用户启用“减少动态效果”时缩短位移并关闭大范围粒子。

视觉素材优先使用经授权的原始素材；无法合法复制或无法提取的素材使用新生成的同类风格位图替代。最终页面不热链原站资源。

## 技术结构

采用 Canvas 2D 绘制游戏场景，并用普通 HTML 按钮承载工具栏和必要的无障碍交互。项目保持现有静态站点的直接访问方式，不引入前端框架或远程依赖。

- `Games/sand-sort.html`：页面外壳、画布、顶部状态、工具栏和通关弹窗。
- `Games/sand-sort-rules.mjs`：倒沙规则、胜负判断、提示候选和不可变状态变换。
- `Games/sand-sort-levels.mjs`：教学关、30 个关卡数据及可解性元数据。
- `Games/sand-sort-renderer.mjs`：Canvas 布局、瓶子绘制、沙层纹理、动画和粒子。
- `Games/sand-sort-game.mjs`：输入协调、动画锁、工具调用、声音、存档和页面状态。
- `Games/sand-sort-assets/`：本地位图与音频素材。
- `Games/sand-sort-rules.test.mjs`：规则与关卡可解性测试。
- `games.html`：新增游戏入口，不修改其他游戏卡片。

## 状态与数据流

`sand-sort-game.mjs` 持有当前关卡状态，并把合法性判断交给规则模块。有效操作先生成移动计划，再锁定输入并交给渲染器播放动画；动画完成后提交新状态、写入撤销栈、保存进度并重新渲染。非法操作不改变状态。

撤销栈只保存有效操作之前的纯数据快照。提示模块基于当前状态枚举合法移动，优先选择合并同色层、完成瓶子或腾空源瓶的操作。重排从该关的已解状态出发执行一串可逆打散操作，并保存其逆序合法移动作为可解性证明。增加空瓶仅影响当前运行中的关卡状态，不修改关卡源数据。

进度使用 `localStorage` 保存当前关卡编号、最高已解锁关卡和金币展示值。关卡运行中的具体瓶子布局不跨刷新保存，刷新后从当前关初始布局开始，以避免版本升级造成旧状态不兼容。

## 容错与降级

- 动画期间忽略重复输入，防止状态和画面不同步。
- `localStorage` 不可用或数据损坏时使用默认进度继续游戏。
- Web Audio 不可用时静音运行，不阻塞任何交互。
- Canvas 尺寸异常时根据最近一次有效尺寸重绘，避免零尺寸画布。
- 提示算法无法找到建议时显示“可以重排或增加空瓶”，不修改游戏状态。
- 所有工具在缺少适用条件时保持可见，但显示明确的不可用反馈。

## 验收与测试

### 自动测试

- 验证所有合法与非法倒沙边界。
- 验证连续同色层和目标剩余容量的移动数量。
- 验证胜利判断、撤销快照和增加空瓶规则。
- 验证 30 个发布关卡都可由求解器完成。
- 验证提示结果始终是合法移动。

### 浏览器验收

- 在桌面视口和 `390 × 844` 移动视口检查布局，无横向溢出或控件遮挡。
- 完成源瓶选择、有效倒沙、非法倒沙、撤销、提示、重排、增加空瓶、重开和下一关流程。
- 检查动画期间的输入锁定和动画完成后的状态一致性。
- 刷新页面后恢复当前关卡与最高进度。
- 检查减少动态效果与静音降级。
- 检查控制台无错误，并确认页面没有广告、分析、商城、登录、外链和运行时网络请求。
- 使用相同视口和关键状态，将原游戏截图与本地实现截图并排比较；修复所有 P0、P1、P2 视觉与交互差异。

## 完成标准

实现只有在规则测试、关卡可解性测试和浏览器验收全部通过，且根目录 `design-qa.md` 标记 `final result: passed` 后才可交付。原作受广告限制的功能必须全部可免费使用，页面必须完全离线运行。

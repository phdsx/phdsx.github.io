# PHDSX 网站产品体验审计

审计日期：2026-08-30  
审计范围：桌面端首页、站内搜索、工具目录、图片压缩工具、游戏目录、博客、黄页、软件作品、AI 雷达、品牌黑名单及 375px 移动端关键状态。

## 1. 用户目标

让访客快速找到一个可直接使用的工具或内容；在图片压缩、资料阅读、实时数据查看等任务中，知道下一步做什么，并相信页面提供的信息。

## 2. 关键步骤与健康度

1. 首页发现与导航：B。首屏价值主张清晰，搜索和快捷入口完整，但首页内容分区较多，功能型内容与阅读内容有交叉。
2. 站内搜索：B。输入后能即时给出结果和无结果状态；结果只显示在首页，工具目录没有同级搜索入口。
3. 工具目录筛选：C+。一级/二级标签逻辑清楚，但默认只展示一个子分类，17 项工具需要多次点击才能看到。
4. 图片压缩工具：B。上传区域、预览、格式说明和使用指南清楚；隐私承诺、大小限制和压缩默认值没有在首屏显式说明。
5. 游戏与博客：B-。游戏入口有封面和类型组织；博客结构完整，但两篇文章都显示为 2020-05-22，与“最新内容”的语义不一致。
6. AI 雷达与品牌档案：C+。AI 雷达加载完成后信息密度和来源入口较好；首次加载期间等待感明显，品牌详情当前记录明确写着“暂未附外部来源链接”，不宜直接呈现为高确定性的“已列入黑名单”。
7. 移动端：B-。导航可折叠，工具页能重排为单列；首页分类条在 375px 下需要横向滚动，部分分类默认不可见。

## 3. 做得好的地方

- 首页把“搜索、快捷工具、热门入口、站点概览”放在首屏，任务入口明显。
- 工具和游戏使用一级/二级分类，并提供数量与当前筛选状态，用户能理解自己正在看什么。
- 图片压缩的空状态很明确，用户知道需要上传图片才能继续。
- 页面具备跳过链接、`main`/`nav`/`search` 等语义结构，筛选标签提供了 `aria-selected` 和键盘方向键逻辑。
- 本地链接检查通过：共扫描 38 个 HTML/CSS 文件，没有发现无效本地引用。

## 4. 最高优先级问题

### P0：统一“工具 / 内容 / 记录”的信息架构

首页“全部功能”把“小说”放进“生活与趣味”工具组，同时顶部导航又把小说放在“阅读”下；这会让“查看全部 17 项工具”的数量与实际可见入口产生认知偏差。建议将首页改为三类明确入口：工具、内容、记录/数据；小说只保留在阅读区，AI 雷达和品牌档案只保留在记录/数据区。

### P1：降低工具发现成本

工具目录默认只显示“文档办公 → Word 辅助”的 1 项，首屏有较大空白。建议默认展示全部工具，或至少默认展开“常用”；保留一级分类作为筛选，二级分类改成可折叠分组。将首页站内搜索复用到工具目录，并把筛选条件同步到 URL，便于返回和分享。

### P1：把信任信息前置到工具操作区

图片压缩页面的“不会上传服务器”只出现在下方 FAQ；上传图片时用户最关心的隐私、支持的最大文件、批量数量、默认质量和输出格式没有即时可见。建议在上传框下增加一行“本地处理，不上传服务器”，并展示大小/格式限制、当前默认设置与预计输出结果。

### P1：给动态数据一个可感知的加载与失败策略

AI 雷达首次打开时，页面经历“正在同步三个来源 / 正在读取”，刷新按钮不可用，约等待数秒后才出现数据。建议使用每个来源独立的骨架屏，显示“已更新时间/预计等待”，超时后保留上次成功数据并提供单源重试，而不是让整页看起来像未完成。

### P1：为品牌档案建立证据等级

品牌详情页同时使用“LISTED / 已列入品牌黑名单”等强判断表达，但当前示例详情明确显示没有外部来源链接。建议至少加入“演示 / 待核验 / 有来源 / 已更新”等证据状态、来源链接、最后核验时间和更正入口；在证据不完整时改用“待核验档案”或“事件记录”，避免把归档判断误读为权威结论。

### P2：修正内容新鲜度和命名一致性

- 博客页显示两篇 2020 年文章，首页却称其为“最新内容”；改成“博客归档”或补充真实更新日期。
- “图片压缩”“照片压缩工具”在首页、工具卡和页面标题之间不一致；统一成一个用户搜索时最容易想到的名称。
- 软件作品仅 1 项时，可增加版本 changelog、最近更新原因或“正在开发”状态，减少页面的空置感。

## 5. 可访问性与响应式风险

- 移动端首页分类条在 375px 下存在独立横向滚动区域；应增加更明显的滚动提示，或改为下拉选择/两行折叠。
- 辅助说明文字大量使用较小字号和浅灰色，建议对 11–13px 的说明文本重新核对对比度，尤其是首页快捷入口和筛选状态。
- 移动端菜单已提供展开/收起语义和 Escape 关闭逻辑，但仍需用键盘/读屏实际验证焦点是否被限制在菜单内。
- 本次未验证上传文件后的成功、错误、取消、超大文件和下载状态，也未做完整 WCAG 对比度、缩放、读屏和键盘路径测试。

## 6. 建议的迭代顺序

1. 先重构首页与目录的信息架构，并统一名称、计数和导航归属。
2. 在工具目录补充搜索、常用默认态和 URL 状态保持。
3. 前置图片工具的隐私与限制说明，补齐成功/失败/重试状态。
4. 为 AI 雷达和品牌档案补充加载、过期、来源和证据等级。
5. 最后处理博客新鲜度、移动端筛选条与小字号对比度。

# 原版汉化调试

- 现象：原版中文 SWF 的早期截图仍为 FOG 加载画面，但元数据最终为 670×450、24 fps、31 帧。
- 已知：Ruffle 的 `load()` Promise 在本环境先于 `metadata` 就绪完成；此前探针在 Promise 完成后固定等 6～10 秒截图，不能据此证明跳转补丁失效。
- 等待 metadata 后仍观察到第 2 帧“点击开始”提示，已否定“仅截图过早”解释。当前假设：在流式时间线尚未完全解析时，根帧 1 的立即 goto(5) 被截到已加载帧，随后被原第 2 帧 stop 暂停。改为根帧 1 stop + onEnterFrame 检查 `_framesloaded >= _totalframes` 后跳转原 `MainMenu`，仅编译这段新加载脚本，不触碰其他原始字节码。下一步截图主菜单验证。
- 原始证据：`.local-tools/tu95-original/original-local-20s.png` 显示原版菜单；`patched-probe.json` 表明汉化 SWF 外部请求为零。
- 字体首次构建失败原因已经确认：OTF 下载仅到 16,103,424 字节，GSUB 等表超出文件末尾。续传到 16,437,364 字节后成功嵌入 326 个字形，无需改 Java 字体实现。
- 禁止重复：不要再次把文件尚未加载完的截图当作主菜单跳转失败；不要重新反编译/编译所有游戏脚本。

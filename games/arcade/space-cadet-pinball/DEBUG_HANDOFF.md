# Browser measurement notes · 2026-10-26

- Gameplay proof: the local WASM table loads; screenshots show the plunger charging, the ball on the upper rail, native mission prompts, and a raised left flipper.
- Rejected measurement approach: replacing `Browser.mainLoop.func` after startup does not instrument the callback captured by the existing Emscripten scheduler. Use the supplied `Module.postMainLoop` hook instead.
- Rejected measurement assumption: every simulation iteration leaves a new visible WebGL framebuffer. Ten-cycle samples alternated between zero difference and 10,498 changed channels, including when the key was released. Reading a cleared back buffer is not evidence of flipper position or input latency. Do not weaken assertions to treat those samples as valid.
- Confirmed measurement correction: sample only after native WebGL draw calls and reject blank back buffers. All ten flipper cycles then produced exactly 3,735 changed channels while held and zero changed channels after release. Keep this instrumentation in tests only; upstream engine bytes remain unchanged.
- The corrected measurement exposed a genuine upstream integration limit: 29.08 rendered FPS. The 60 Hz Emscripten loop was drawing on every second callback due to the native default update/render ratio. Hypothesis and minimal fix: supply a native INI with both rates set to 60 before engine startup; the same browser benchmark must then show at least 30 rendered FPS, with no changed engine bytes or lost gameplay input.
- Final result: 33 browser checks pass. With the native INI update/render rates both set to 60, the measured engine drawing rate is 56.04 FPS under the instrumented headless run. Real drawn-pixel response is 11 ms. No outstanding repeated defect remains.
- Visual inspection after the first passing suite caught a separate focus defect: clicking fullscreen moved focus to the toolbar, so SDL stopped drawing and a subsequent canvas resize appeared black. The fix explicitly restores iframe/canvas focus after fullscreen transitions and sound toggles. The regression must observe new native rendered frames after fullscreen and every viewport resize; geometry assertions alone are insufficient.

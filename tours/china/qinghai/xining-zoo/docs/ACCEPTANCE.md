# 验收报告

日期：2026-10-04。版本：0.2.0。

**工程浏览功能已通过本次检查；“写实三维园区、1:1 还原、三机位照片匹配”未通过最终验收。** 当前只交付明确标注状态的资料核对版，不把未完成的场景作为写实效果成品。

|项目|本次环境|

此环境没有用实体独立显卡做基准测试，也没有验证 Safari / Firefox。因此不能据此承诺普通独显设备达到 60 FPS。

|鸟瞰|鼠标旋转确实改变相机；全园复位后回到预设位置|

|碰撞|从有效落点向八个方向连续分步推进，未越出参考道路；建筑平面、水面、园界阻挡检查通过|

键盘位移是软件渲染下的输入检查，不是步速测量。为避免长时间掉帧引起突然跳跃，每帧移动时间有上限；严重低帧率下实际推进速度会降低。

## 地形一致性检查

新增 [surface-check.mjs](../tools/surface-check.mjs)，直接使用随包 Three.js 的 Raycaster 验证实际三角面，不以高度函数自身作为预期答案。非共面合成地形及真实 DEM、10 米与 20 米两档网格均通过；测试同时检查贴地图层的覆盖面积、三角面朝向、UV 插值、面内高度，以及线段与等高线贴合。

Node 检查共 320 个采样点，另有四角边界与面片内检查；浏览器另检查 64 个点。浏览器高度查询与射线交点最大差值约 0.00000650 米（容差 0.0001 米）。这些数字仅反映程序内部浮点一致性，**不是 DEM 与现场的测量误差**。原始记录见 [surface-test-results.json](surface-test-results.json)。

## 运行表现

- 本轮首次页面进入至检查可用状态约 **2.29 秒**，包含测试等待；不是纯网络传输或严格冷启动指标。
- 本轮软件渲染、1920×1080、低画质、DPR=1 的静止鸟瞰采样约 **6 FPS**。这个环境不能替代实体目标显卡测试。
- 鸟瞰视图约 **21 次绘制调用、32668 个三角形**。三角数比 v0.1 增加，是因为贴地图层会沿地形边分割；绘制调用仍保持合批。
- 近景/远景地形使用 10 米 / 20 米网格。道路、轮廓与等高线同步 LOD；有视锥裁剪。DPR 上限低/中/高分别为 1 / 1.5 / 2。
- 当前没有现场贴图和大模型，纹理计数为 0。不能拿当前轻量场景的性能预测写实版性能。
- 没有启用昂贵后期效果和实时阴影。植物实例化、区域 GLB 流式加载、模型/纹理压缩待真实资源就绪后验证。

## 可复现检查

先启动 `node server.mjs`。可选安装 Playwright 后运行 `node tools/browser-check.cjs`。若使用系统 Edge，将 `BROWSER_EXECUTABLE` 环境变量设为其可执行文件路径；否则使用 Playwright 安装的 Chromium。脚本默认启用 SwiftShader，以复现本报告的功能检查环境。它会刷新 `docs/test-results.json` 与截图；不是独显基准测试脚本。

源码语法检查可运行 `npm run check`。几何检查可运行 `node tools/surface-check.mjs` 或 `npm run test:surfaces`，无需安装额外 npm 依赖。数据重建可运行 `python tools/prepare-data.py`（需要 Pillow），不会自动改进原始数据精度。

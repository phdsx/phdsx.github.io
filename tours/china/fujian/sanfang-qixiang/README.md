# 三坊七巷 · 街巷之间

实际可运行的 Three.js 静态项目，入口 `index.html`。当前交付是**真实地图轮廓 + 约 150 米照片近似样板**，并非全区 1:1 测绘复原，也尚未达到实景建筑摄影级视觉。界面、对照页和来源清单均明确标出这一边界。

## 启动

需要 Node.js 18 或以上。运行时不需要 npm 安装，不依赖 CDN、账号或密钥。

```powershell
cd D:\code\html\phdsx.github.io\tours\china\fujian\sanfang-qixiang
npm start
```

打开 `http://127.0.0.1:5190/`。也可使用任意静态 HTTP 服务或将整个目录部署到 GitHub Pages。不要直接以 `file://` 双击打开；页面会提示正确启动方式。`PORT` 环境变量可以更改端口。运行命令也可简写为 `node scripts/serve.mjs`。

本站的 `tours.html` 已增加福建 / 三坊七巷入口及站内搜索索引。没有执行远程发布。

## 坐标与精度

- 1 世界单位 = 1 米。WGS84 原点为经度 119.292°、纬度 26.086°。
- 使用 WGS84 椭球的地理坐标 → ECEF → 局部 ENU：X 向东，Y 向上，Three.js Z 向南。显示地面为水平面，尚无真实高程数据。
- 浏览器和预处理脚本使用相同的椭球参数，逆变换在椭球面上求交；没有把 GCJ-02 / BD-09 当成 WGS84 混入。
- 南后街中心线长 **624.70 m**，由本次 OSM 折线在局部 ENU 中计算。不是路面测量值；其他资料的长度可能使用不同起终点或道路定义。
- OSM 轮廓只删去偏差小于 2.5 cm 的共线点，保存原始经纬度、way ID、version、timestamp。底图未用随机格网补齐。
- 区域是按工作范围筛选的矩形，不是官方保护区界线。680 个轮廓包含周边建筑，不等于 680 栋保护古建，也不能说明全部古建都已绘入。

## 估算和缺失

`data/site.json` 为每栋记录 `heightEvidence`、`roofEvidence` 和 `detailEvidence`。没有建筑带 `height` 标签；只有 1 个轮廓带层数，可据层数作估算。其余默认檐高 5.4 m。样板例外值和类型说明在 `scene.js` 的 `profiles` 中（5.3–7.7 m），全部是视觉估算。灰瓦双坡屋顶的朝向依据最长轮廓边推断，坡度和结构未确认。

每条道路的宽度都标为估算：南后街 12 m；衣锦坊 5 m；文儒坊 4.6 m；郎官巷 4.2 m；塔巷 4 m；黄巷 4.8 m；安民巷 4.5 m；宫巷 5 m；吉庇巷、光禄坊各 10 m。**这些宽度不是现场测量，尚未还原真实的沿线宽窄变化。**路面来自中心线加估计宽度，实际可见空间同时受到 OSM 两侧轮廓制约。

叶氏民居照片缺少门牌到轮廓的可靠对应，候选是 way 985162854。该模型不能用于判断真实故居的边界或准确位置。比较机位也没有相机标定：北口接近另一张 2023-10-20 照片 GPS；爱心树使用 2023-08-25 拍摄点；叶氏民居为对候选立面的近似正视机位。照片 GPS 是相机位置，不是树或建筑位置。

缺少逐栋测绘、高程、屋顶和院落平面、沿街连续立面、2023 年道路边界和商铺设施清单。因此院落与商铺内部不开放进入。没有为填空添加通用古建筑模型、虚构店名、整排装饰灯笼或随机街道。牌坊的四盏灯来自北口照片，但位置与尺寸为估计；牌坊雕饰仅用照片裁切的小范围表面细节，不能代表浮雕几何的真实复原。

## 操作

- 鸟瞰：左键旋转、滚轮缩放、右键平移；触屏单指旋转、双指缩放 / 平移。
- 步行：眼高 1.65 m，垂直视角 54°，速度约 1.45 m/s；WASD / 方向键移动，按住画面拖动观察。可点击按钮锁定鼠标，Esc 释放。
- 手机：拖动观察，方向按钮移动。只做了触屏模拟验证，未测试真实手机。
- 地点按钮和北朝上的小地图可以跳转；镜头使用平滑过渡，步行跳转先抬升绕开低层建筑。
- 开关地名和精度图层、切换画质、保存当前三维截图、查看来源。地图比例尺按米制坐标绘制。

碰撞使用真实轮廓、树干和牌坊柱的水平空间哈希，人体半径 0.32 m，移动按小步长分别检测 X/Z 轴。对未绘入地图的墙体无从检测，屋檐和非承重细节也没有独立碰撞；这不等于完整物理模拟。

## 渲染与性能

本地 Three.js 0.180.0，sRGB 颜色管理、ACES 色调映射、克制曝光、同向日光 / 天空光、柔和阴影。无泛光、景深或高饱和滤镜。白墙、木材、树皮使用 CC0 PBR color / normalGL / roughness；灰瓦和铺装用程序材质与几何。所有通用材质均非现场扫描。纹理周期有明确米制标称 / 估算，实际材质外观仍有明显近似。

分区合并减少 draw call；鸟瞰显示所有地图体块，步行只显示附近 350 m 内街区。细立面显示距离 130 m；瓦片以 InstancedMesh 表现，节能不显示，均衡 42 m、精细 75 m。叶片也是实例。当前资产小，初次读取整个轮廓 JSON，**没有大型模型的网络流式加载、KTX2 压缩或光照烘焙**。WebP 降低材质传输量，原始下载 ZIP 不参与网页加载且被 Git 忽略。

实际测试环境及数字见 `evidence/test-results.json`、`docs/VALIDATION.md`。帧率受到 60 Hz 显示 / requestAnimationFrame 限制，不代表 GPU 极限，也不代表移动设备性能。

## 文件与复现

`index.html` / `style.css`：界面与异常提示；`app.js`：渲染、定位、小地图；`scene.js`：地理几何、近似细节、LOD；`geo.js`：WGS84 椭球转换和碰撞；`navigation.js`：两种模式；`materials.js`：材质及本地资源回退。

`vendor/` 是 MIT 的本地 Three.js 核心、OrbitControls 和 BufferGeometryUtils。`data/osm-map.osm` 是未修改原始 API 结果；`data/osm-raw.json` 是初步 Overpass 查询结果，仅存档，正式场景未混用它。`data/site.json` 是衍生数据；`data/sources.json` 和 `references/*-metadata.json` 保存许可与照片元数据；`textures/manifest.json` 保存材质来源、尺寸、变化和原 ZIP SHA256。

```powershell
npm run check
# 浏览器测试需安装开发依赖；可用 CHROMIUM_PATH 指向已装 Chromium。
npm install
npx playwright install chromium
npm run test:browser
```

`scripts/prepare_data.py` 读取存档 OSM 生成米制数据及布局图，需 Python + Pillow；不发网络请求。`scripts/prepare_textures.py` 可从已保存源 ZIP 重新生成 CC0 表面及 CC BY-SA 牌坊裁切。源码代码使用仓库 AGPL-3.0-or-later；独立地图和资产许可见 `SOURCES.md`，不能由代码许可重新授权。
